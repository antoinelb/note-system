# CSS draws the markup; Typst compiles only what it must

## Context

`adr/2026-08-cursor-split-rendering.md` kept the editor's prose as compiled Typst SVG at all times, splitting only *which* fragment a cursor move belongs to — above the caret, below it, or the raw `<textarea>` line itself.
That still meant every `j`/`k` re-keyed a region's content hash, so `FragmentCache` missed, a fresh compile went out, and `adr/2026-08-region-recompile-keeps-the-stale-svg.md` had to invent a `Side`-keyed shelf just to keep the *previous* line's SVG on screen while the new one compiled — the prose above and below the caret visibly reflowing and repainting on every vertical move, which is exactly the "jenky" feeling `region-recompile` was written to paper over rather than remove.
The actual content of a paragraph, a heading, a list item, an emphasis span — the overwhelming majority of what a note is made of — is markup Typst does not need to lay out specially: a browser can draw a heading, a bold span, a bullet, or a link edge in CSS as legibly as `typst-svg` can, without a compile in the loop at all.

## Decision

**`src/markup.rs` holds one pure function, `markup::model`**: given a block's source text, it walks the `typst-syntax` parse tree once and returns two things — a `Vec` of role-carrying, block-relative byte spans (`Span`-shaped: a `Role` — text, strong, emphasis, raw, link, meta call, marker (a heading's `=`, a list's `-`, or a quote's leading `> `), or checkbox — and the `[start, end)` range inside the block) and a verdict, `Css` or `Typst`.

**The verdict is decided by node kind and callee name alone — never by scanning characters.** A block draws as CSS when every top-level node in its parse tree is either a plain markup node (heading, list item, strong, emphasis, quote marker line, plain text, `Space`) or a `FuncCall` whose callee identifier is on the app's own allow-list: `meta`, `l`, `quote`. Anything else — an `Equation`, a `#table`, a `#figure`, a `#image`, a `Code` block, a `FuncCall` to any callee not on the allow-list — falls back to `Typst`. The allow-list is read off the call's own AST callee node, the same way `blocks::segment`'s preamble fold already reads a `meta` call's identity, not off a string prefix.

**`SyntaxKind::Error` is a deliberate exception and stays `Css`.** A half-typed call under the caret — `#l(` with the closing paren not yet typed, an unterminated `#quote[` — parses with an `Error` node somewhere in its tree. Falling back to `Typst` for that block would hand it to the compiler mid-keystroke and flash a real compile error at the user for the ordinary, transient act of typing a call open before closing it; treating `Error` as still-`Css` instead means an unfinished construct just renders as inert text until it parses clean, exactly the forgiving posture the raw `<textarea>` gave the active line for free before this change.

**Inactive, active, and selected blocks all draw the same spans.** Before this ADR, only the active line was a real `<textarea>`; every other block was a compiled SVG, and the boundary between "line I can edit" and "line I can only look at" was also the boundary between two different rendering pipelines. Now every block — whichever state it is in — renders as the same `Span`s from the same `markup::model` call; entering or leaving a line changes which spans get a caret, a selection highlight, or an editable overlay drawn on top of them, not what the spans *are*. A cursor moving from line 40 to line 41 reflows nothing above or below it and compiles nothing, because nothing recompiles on a cursor move at all.

**The SVG fallback becomes one widget per block, cached by content — not by cursor side.** A block whose verdict is `Typst` renders through the same `FragmentCache` machinery as before, but keyed by that one block's own content hash, the way `BodyCache` already keys the table's card bodies by path. This retires the region model outright: `Side`, the two-region split at the cursor, and the `Side`-keyed stale shelf `region-recompile-keeps-the-stale-svg.md` built to hide the reflow all go, because there is no longer a region whose boundary moves with the caret — a `Typst`-verdict block's cache entry is stable across every cursor position that doesn't touch that block's own text.

**The preamble block stays on the `Typst` fallback.** `blocks::segment`'s leading `#import`/`#show`/`#meta` fold (`adr/2026-08-per-line-block-segmentation.md`) still produces one block whose top-level children include a `ModuleImport` and a `ShowRule` — neither is markup, and neither is a `FuncCall` on the allow-list, so the verdict is `Typst` by the same node-kind rule as any other unrecognised construct. This is not a special case carved out for the preamble; it falls out of the same allow-list every other block is judged against, and it is what keeps the compiled meta line rendering exactly as it always has — `#meta` calls with no CSS-drawable rendering intent of their own.

## Rejected

- **Keep everything compiled, and just make the compile cheaper or hide it better** — the status quo this ADR replaces. `region-recompile-keeps-the-stale-svg.md` already tried the "hide it better" half: a cursor move still re-keyed a region, so it still recompiled and still reflowed the prose around it, just with a stale frame shown for the duration. No amount of caching removes the reflow, because the reflow's cause is that the *content of the compile unit* changes shape (its boundary is the caret) on every line move. Only removing the compile from the common path removes it.
- **Widen the allow-list to cover more constructs speculatively** (tables, figures, arbitrary user functions) — rejected as scope creep: the allow-list is deliberately the three calls the app already owns semantically (`meta`, `l`, `quote`), not an attempt to reimplement Typst layout in CSS. Anything wider is real engineering with no note in the vault asking for it yet, and the fallback already covers it correctly.
- **Detect "safe to draw as CSS" by scanning the raw source text** (balanced brackets, a regex for call syntax) — the same objection `per-line-block-segmentation.md` already recorded against counting brackets in source text: it cannot see past strings, comments, or an unterminated construct, and the never-regex rule forbids it outright. `typst-syntax`'s own tree is the only source of truth for what a block's shape is.

## Consequences

**The editor and the export pipeline now agree on appearance without sharing a mechanism, and that divergence is accepted, not accidental.** The editor draws CSS-verdict prose with styled HTML spans laid out by the browser; `typst compile` — the vanilla CLI, the embedded compiler for `Typst`-verdict blocks, and `BodyCache` for the table's card bodies — still owns every pixel that ships as an export or a card. These are two different renderers agreeing to look the same, not one renderer used twice. That is acceptable for three reasons: the verdict is conservative by construction, so anything the CSS renderer does not fully own — anything not on the allow-list, anything with an unrecognised node — falls back to the real compiler rather than being approximated; the plain `.typ` file stays the source of truth regardless of which renderer draws it, and it still compiles standalone with the vanilla `typst` CLI exactly as this ADR's constraints require; and the table's card bodies never touch the CSS path at all — they have no cursor and no editing state to keep in sync with a browser layout, so `BodyCache` compiling them whole is not a divergence this ADR introduces, only one it declines to close.

**This amends the "app never restyles note bodies" principle in `adr/2026-08-shipped-ui-is-the-spec.md`** (sourced from `adr/2026-07-design-language-own-phase.md`: *"the app never restyles them; the wireframes' serif prose stands in for the template's own output"*). That principle held everywhere prose appeared until now: every block, active or not, was compiled Typst SVG, so the browser only ever displayed a rendered image — it never laid out a heading, a bold span, or a bullet itself. This ADR ends that: for a `Css`-verdict block, the browser now lays out headings, strong/emphasis spans, list markers, and quote roles from `Piece` spans, which is the app itself doing the restyling the principle named. The amendment is deliberate and narrow, not a quiet reversal, and it is narrow for a specific reason: the CSS spans are not invented typography competing with the template's own — they are drawn from the same `typst-syntax` parse tree the compiler itself reads, so a `Css`-verdict heading is CSS reproducing the compiler's own structural call ("this node is a heading"), not the app deciding independently what a heading should look like, and a block the CSS renderer cannot faithfully reproduce falls back to the compiler outright rather than being approximated. Read that way, the principle survives for what it was actually guarding against — the app inventing a look the template disagrees with — while no longer covering *which renderer* draws the template's agreed-upon look. The principle's original scope keeps applying without qualification to what ships as output: `typst compile`'s export path and `BodyCache`'s table card bodies (previous paragraph) never touch the CSS renderer and remain the template's own output exactly as shipped-ui-is-the-spec.md describes. `adr/2026-08-shipped-ui-is-the-spec.md` carries an inline amendment note on that bullet; `adr/2026-07-design-language-own-phase.md`'s Context is left unedited, because it is quoting `wireframes-v0.md` verbatim and rewriting a citation that is itself the historical record would falsify it — the same distinction `shipped-ui-is-the-spec.md` already draws between a pointer and a subject citation.

**This supersedes the rendering half of `adr/2026-08-cursor-split-rendering.md`.** That ADR's own scope note already limited itself to "which blocks a compile groups together for rendering" while leaving `blocks::segment` and the one-block-per-physical-line grain untouched; this ADR keeps that grain and changes what most blocks render *with*, not what a block *is*. It also retires the two ADRs written to patch the region model's own rough edges: `adr/2026-08-region-recompile-keeps-the-stale-svg.md` (the `Side`-keyed shelf it built no longer has a region to shelve) and `adr/2026-08-region-click-lands-on-the-boundary-block.md` (a click now lands on the block a pointer actually hit, because every block is its own widget again — though placing the caret at the exact byte offset inside a clicked, non-active block remains unimplemented; a click still only activates the block, same as before this ADR).
