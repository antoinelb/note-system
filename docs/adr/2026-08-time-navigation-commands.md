# The palette's "open next" creates; "open previous" only ever finds

## Context

`2026-07-time-navigation-derived-not-stored.md` decided that previous/next day is "a navigation action that resolves to the nearest existing note in that direction" — deliberately never a write, because a template-seeded `{{next}}` link is a link to a file that does not exist yet, and seeding one per daily note produces 365 false open loops a year.
That reasoning holds exactly as written for *templates seeding links inside a note's own text*.

The todo list also asks the palette to gain nine time-navigation commands: "open daily" (renamed from "go to today") plus previous/next for daily, weekly and season.
"Open next weekly" from the last week of a season, run on a vault that has never had a note written past today, has nothing existing to resolve to — under the 2026-07 rule taken literally, the command would do nothing, which is not what "open next" says it does.

## Decision

**"Open next `<scale>`" creates the note from the template when the target period has no note yet.**
This is not the same act the 2026-07 ADR ruled out: that ADR is about a *template silently seeding a link inside another note's text*, decided by the app with no user in the loop.
A palette command is the opposite of silent — the user typed "open next daily" (or pressed a chord) and asked, by name, for the next period's note to be open in front of them.
The file appearing is what the command promised; it seeds no link inside any other note, and it never runs unless a person invoked it, so it never becomes a false open loop the way an autogenerated `{{next}}` would.

**"Open previous `<scale>`" stays exactly the 2026-07 rule: nearest existing note in that direction, never a write.**
There is no symmetric argument for creating backward — "previous" asks to see something that already happened, and a period with no note is not a period the user wrote anything for.
When nothing exists before the anchor, the command is a no-op: the selection holds, same as before the keystroke.

**The anchor is the open note's own date**, computed once per invocation as `logs::selection_date(&selected.0, &selected.1).unwrap_or(today)`.
A selection at another scale (a season note open, "open next daily" invoked) still yields a date — `selection_date` answers for all three time scales — so the six relative commands are total: they never need a special case for "nothing is open" or "the wrong scale is open".
`unwrap_or(today)` only matters for a selection `selection_date` cannot place (a non-time note, or none), which the app's own selection model does not produce on the logs screen.

**"Open weekly" / "open season" are plain, chordless siblings of "open daily"**: always today's own period, `select.call` with no creation logic, mirroring what `time::week_id(today)` / `time::season_id(today)` already resolve to.
They never create, because today's own week and season note is either already on disk (the common case for a vault in daily use) or the user reaches for "open next" from the previous period to write it — "open weekly" answering "what is today's week" is a read, not a commitment to write one into existence.

**The user's word is "season"**, in every label — `NoteType::Seasonal` is the enum's name, chosen before the palette existed; the palette speaks the vault's vocabulary, not Rust's.

The creation half is one callback, `create_time_note: Callback<(NoteType, String)>`, lifted out of the plain-Enter arm so "open next" and Enter share it — Enter's own observable behaviour (create the day/week/season the logs screen currently shows no note for) is unchanged, it now just calls the shared callback instead of inlining the same match.

## Alternatives rejected

- **"Open next" also only resolves to an existing note, doing nothing past the last one** — matches the 2026-07 rule most literally, but makes the command lie about its own name on a vault with no future notes yet, which is the common case for "open next" the day it is reached for.
- **A separate, un-derived confirmation step before creating** ("create tomorrow's note?") — the plan's no-hard-blocks invariant already rejects friction on a gesture the user named explicitly; Enter creates the selected empty day today with no confirmation, and "open next" is the same act reached by a different door.
- **Anchor on `today` always, ignoring the open note's own date** — breaks stepping through a run of days from anywhere but today's date; a user reading the season chain three months back would have every "open next" jump back to the present instead of advancing from where they are reading.
